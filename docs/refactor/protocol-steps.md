# Refactor plan: protocol steps with JSON input

Status: planned, not implemented. This is a working plan for one breaking
refactor. It is intentionally not linked from the documentation index or
embedded in the binary; delete it when the refactor lands and the owning
documents describe the result.

## Decision summary

- The `protocol` tool takes `steps: object[]` instead of `requests: string[]`.
  The `*** Begin Request` envelope is removed.
- Every protocol receives one JSON object, `input`, instead of request headers
  plus a string body. Headers are removed from the model interface, the
  `Protocol` trait, the WASM ABI, the SDK, help pages, and documentation.
- Steps can carry a minimal control layer: `id`, `if`, `for` with `max`, and
  `show`. There is no general-purpose scripting.
- MCP tool, prompt, and resource calls pass their arguments as `input`
  directly. Header argument coercion is removed.
- No compatibility is kept. The session database, WASM ABI, and retrieval
  sidecar versions are bumped; old data is neither read nor migrated, and every
  code path that exists only for older shapes is deleted.

## Rationale

All supported providers deliver tool arguments as JSON generated by the model.
The envelope was modeled on `apply_patch`, whose raw-text benefit exists only
for free-form custom tools, which URI Agent does not use. Under JSON function
calling the envelope therefore added rules (headers, `*** Body:` separator,
last-end-line termination, the extra empty line for a trailing newline)
without removing a layer of escaping, and it forced JSON arguments such as MCP
tool arguments into a JSON string, which doubled their escaping.

The model makes the formatting mistakes, not the runtime, so the interface
should use the shape models are trained on most: a flat JSON object per call.
Text content keeps exactly one JSON string layer, which no JSON tool can avoid;
structured content needs no extra layer. The only new concepts are the address
string, five control fields, and a one-comparison expression.

Full scripting (for example Python or JavaScript in a sandbox) was rejected:
weaker models leave the provided functions for the standard library, and
scripts fail after side effects instead of before them. The step form is
validated completely before anything runs.

## Model interface

```text
help(protocols: string[])
protocol(steps: object[])
replace(path: string, old_text: string, new_text: string)
apply_patch(patch: string)
```

`help` is unchanged: a protocol's contract must still be loaded before use.

### Step object

| Field | Type | Meaning |
| --- | --- | --- |
| `read` | string | Address to read, `<protocol>://<target>`. Exactly one of `read` and `exec`. |
| `exec` | string | Address to execute. |
| `input` | object | Protocol input. Fields are defined by the protocol's help page. Omit when the operation takes none. |
| `id` | string | Name for later references. `[a-z][a-z0-9_]*`, unique within the call. |
| `if` | string | Condition; the step runs only when it is true. |
| `for` | string | `<name> in <reference>`; runs the step once per list element. Requires `max`. |
| `max` | integer | Upper bound for `for`, 1..=32. The call fails validation if the list is longer. |
| `show` | string | `all` (default), `errors`, or `none`; controls whether the step's output enters the result. |

The tool schema declares every field with a fixed type and no unions.
`steps` holds 1..=8 steps; a call expands to at most 64 protocol operations.
A step without control fields behaves like a request in the current batch.

Examples:

```json
{"steps": [
  {"read": "file://src/main.rs"},
  {"read": "search://src", "input": {"query": "credential refresh flow", "mode": "hybrid", "glob": "**/*.rs"}},
  {"exec": "bash://run", "input": {"script": "cargo test"}},
  {"exec": "tasks://001/send", "input": {"text": "yes\n"}},
  {"exec": "github-mcp://tools/get_issue", "input": {"repo": "acme/api", "number": 42}}
]}
```

```json
{"steps": [
  {"id": "tests", "exec": "bash://run", "input": {"script": "cargo test"}, "show": "errors"},
  {"if": "not tests.ok", "read": "file://target/test.log"},
  {"id": "issues", "exec": "github-mcp://tools/list_issues", "input": {"repo": "acme/api"}, "show": "none"},
  {"for": "issue in issues.json.items", "max": 20, "if": "issue.comments > 0",
   "exec": "github-mcp://tools/get_issue",
   "input": {"repo": "acme/api", "number": "{{ issue.number }}"}}
]}
```

### Expressions

Grammar: `["not"] operand [comparator operand]`.

- Operands are references or literals. References start with a step `id` or a
  `for` variable and continue with `.field` and `[index]` segments.
  Literals are numbers, double-quoted strings, `true`, `false`, and `null`.
- Comparators: `==`, `!=`, `<`, `<=`, `>`, `>=`. Ordering comparators accept
  two numbers or two strings.
- A condition without a comparator is true when the value is `true`, and
  false when it is `false` or `null`; any other type is an error.
- There is no `and`, `or`, arithmetic, function call, assignment, or loop other
  than `for`.

Step values available to references:

| Reference | Value |
| --- | --- |
| `<id>.ok` | `true` when the operation succeeded |
| `<id>.text` | Complete text output, not the truncated preview |
| `<id>.json` | Structured output, or `null` when the protocol returned none |

A `for` step's value is the list of its per-element values. References may
point only to earlier steps.

### Value substitution

- In `input`, a string value that is exactly `{{ <operand> }}` (optional
  surrounding spaces inside the braces) is replaced by the referenced value
  with its JSON type preserved.
- Any other string in `input` is literal, including strings that contain
  `{{` such as `${{ secrets.TOKEN }}`. A literal string that is exactly a
  placeholder is written as `{{ "{{name}}" }}`.
- In `read` and `exec` addresses, placeholders are replaced as text inside the
  string; the referenced value must be a string, number, or boolean.
- `input` text that a protocol executes (for example a shell script) never
  receives substitutions. Data reaches scripts through dedicated input fields
  such as the shell `env` object.

### Validation and execution

1. Before any operation runs, the whole call is validated: tool arguments,
   field presence and types, protocol existence, loaded help, `read`/`exec`
   support, reference targets and ordering, `for`/`max` pairing, and
   expression syntax. Any failure rejects the entire call with a message naming
   the step and field and showing a correct example.
2. Steps run in order. `for` elements run sequentially.
3. A step whose `input`, address, or `for` source references a failed or
   skipped step is skipped with that reason. An `if` may read `.ok` of a failed
   step. A `for` list longer than `max` fails the step.
4. An operation referenced by a later step is never promoted to a background
   task; it runs in the foreground under its own deadline. Unreferenced
   operations keep the current foreground-grace promotion.
5. Protocol validation of `input` happens when the step runs, because
   `input` may contain substitutions.

Result format: one section per operation, `*** Result <n> of <m>: ok|error|skipped`
(loop elements use `<n>.<k>`), followed by the output unless `show` hides it.
Truncation and `file://` preservation of large output are unchanged.

### Rejected shapes

No lenient alternatives are accepted. Examples that fail validation: `input`
given as a string, both `read` and `exec`, `for` without `max`, an unknown step
field, a string instead of the `steps` array.

## Runtime and protocol API

### `Protocol` trait

- `ProtocolRequest { uri, target, input: &serde_json::Map<String, Value> }`
  replaces `headers` and `body`. `RequestHeader`, `header_value(s)`,
  `reject_unknown_headers`, `Comparison`, and `parse_comparison` are deleted.
- Protocols deserialize `input` into typed structs with
  `#[serde(deny_unknown_fields)]`. Deserialization errors are the validation
  errors; each protocol's help page lists the same fields.
- `read`, `read_output`, and `exec` return
  `ProtocolOutput { text, json: Option<Value>, images }`. `json` is the value
  exposed as `<id>.json`. The truncation and spill logic applies to `text`;
  references use the complete text.
- `ProtocolRegistry::read_for_model`, `exec_for_model`, `read_static`,
  `exec_static`, and `load_help` take `input` instead of headers and body.
  `load_help` passes an empty object.
- Comparison prefixes are removed. They were documented as general but only
  `search` `context` and `limit` implemented them; those become plain integers.

### Step executor

The step parser, validator, expression evaluator, substitution, and result
formatting live in `src/builtins/model_tools.rs` (or a sibling module it owns).
The envelope parser, `CORRECT_FORM`, `RESERVED_HEADER_NAMES`, and their tests
are deleted.

## Built-in protocol input mapping

General rules: repeated headers become arrays; `true`/`false` strings become
booleans; numeric strings become numbers; the former body becomes the named
field below. Routes are unchanged unless noted. `help` routes take no input.

| Protocol | Route | `input` fields |
| --- | --- | --- |
| `file` | `file://<path>` read | `offset`, `limit`, `tail` (integers), `line_numbers` (boolean), `glob` (string). Same exclusivity rules. |
| `search` | `search://<root>` read | `query` (required except `mode: "status"`), `mode`, `glob`, `literal`, `ignore_case`, `context`, `limit`. `context`/`limit` are plain integers with the existing clamps. |
| `search` | `search://<root>` exec | `mode: "index"`, optional `glob`. |
| `tasks` | `tasks://<id>` read | `wait` (integer seconds). |
| `tasks` | `tasks://<id>/send` exec | `text` (string, sent byte-for-byte; the empty-line rule is gone). |
| `tasks` | `summary`, `cancel`, `eof`, `interrupt` | none |
| `bash`, `pwsh` | `<shell>://run` exec | `script` (required), `background`, `interactive` (booleans), `timeout` (integer seconds, `0` disables), `env` (object of string values, new). |
| `https` | `https://search` read | `query` (required), `provider`, `limit`, and each provider's options; repeatable options (`search_query`, `include_domain`, `exclude_domain`, `additional_query`, `subpage_target`) become string arrays. |
| `https` | `https://<host>/<path>` read | none |
| `context` | history, notes, and status reads | Former headers as typed fields; `types` becomes a string array; search routes take `query`. |
| `context` | `rollover` exec | `handoff` (optional string). |
| `context` | `notes/add`, `notes/<nid>/replace` exec | `title` (required), `content` (required). |
| `context://sessions/…` | all routes | Former headers as typed fields; `types` becomes a string array; `search` takes `query`. |
| `collaboration` | `participants`, `status/<target>` read | `scope`. |
| `collaboration` | `name` exec | `name`. |
| `collaboration` | `send/<target>` exec | `message` (required), `delivery`, `reply`, `scope`, `in_reply_to`. |
| `finder` | `finder://<root>` exec | `question` (required). |
| `uri-agent-docs`, `<name>-skill`, `wasm_plugin` | all routes | none. These protocols now reject any `input` field instead of ignoring headers. |

### MCP

| Route | Operation | `input` |
| --- | --- | --- |
| `tools`, `resources`, `resource-templates`, `prompts`, `tools/<name>` | read | none |
| `resources/read` | read | `{"uri": "<raw resource URI>"}` |
| `prompts/<name>` | read | prompt arguments (string values) |
| `tools/<name>` | exec | the tool's arguments, passed unchanged |

- `ProtocolOutput.json` for tool calls is `structuredContent`; when absent and
  the only content block is text that parses as JSON, that parsed value.
  `isError` makes the operation fail (`ok == false`).
- Delete `map_arguments`, `schema_property`, `schema_type`, `coerce_values`,
  `coerce_scalar`, and their tests. Keep a top-level `required` check.
- Delete `render_legacy_help` and the empty-`help_dependencies` path; MCP
  records must declare `["mcp"]`.
- Rewrite `render_shared_help` for the step form.

## Code that embeds the old format

Each of these is rewritten to emit or parse the step form; fallbacks for the
older `{uri, body}` argument shape are deleted.

- `src/prompts.rs`: protocol rules in the system prompt, task-accepted and
  interactive-task messages, truncated-output footer.
- `src/runtime.rs`: task notification read instruction; envelope tests.
- `src/task.rs`: error text that names `tasks://` reads and cancels.
- Continuation hints with envelopes: `file.rs`, `context.rs`, `sessions.rs`,
  and the `tasks` summary. They emit single-line step JSON.
- `collaboration.rs`: the reply instruction inside the XML envelope becomes
  a step JSON example instead of `<header>` elements.
- `src/tui/app/render.rs` and `src/tui/app.rs`: display parser and titles read
  `steps`; the `{uri, body}` fallback is removed.
- `src/acp/v1.rs`: `tool_title` and `tool_kind` read `steps[0]` and
  `exec` fields.
- `src/builtins/history.rs` and the `searchable_records` SQL in
  `src/session.rs`: the private-call filter checks every step address for
  `context://`. This also fixes the existing gap where `protocol` calls
  bypass the filter because only `arguments.uri` was checked.
- `src/builtins/finder.rs`: child system prompt; delete the legacy `tasks`
  help-dependency restore path.

## Remove standalone `sessions` protocol remnants

Saved-session access moved to `context://sessions/…` earlier, but the former
standalone protocol still exists in code. Delete it in phase 1:

- `src/builtins/sessions.rs`: `SessionsPlugin` still implements `Protocol`
  with the descriptor name `sessions`, and carries a `base_uri` switch between
  `sessions://` (`SESSIONS_BASE_URI`, used only by the test constructor
  `with_archive`) and `context://sessions/`. Turn it into an internal handler
  that only `ContextPlugin` calls, with the fixed `context://sessions/` base;
  delete `SESSIONS_BASE_URI`, `with_archive`, the `base_uri` field and
  parameters, and the `Protocol` implementation and descriptor.
- The saved-session help text mentions `sessions://` calls as omitted from
  results; it names only `context://`.
- The private-call filters in `src/builtins/history.rs` and the
  `searchable_records` SQL in `src/session.rs` stop matching `sessions://`
  (they are rewritten for steps anyway).
- Tests in `sessions.rs`, `history.rs`, and `session.rs` that build
  `sessions://` requests or arguments move to `context://sessions/…`.
  Guard assertions in `context.rs` that output does not contain `sessions://`
  are deleted with the base-URI switch they protected.
- Keep `SessionCompletionPlugin` and the `@@<session-id>` composer completion;
  they are not part of the removed protocol.

## WASM ABI and SDK

- `ABI_VERSION` becomes 9; version 8 is rejected like every older version.
- `HandlerRequest::Protocol { protocol, operation, uri, target, input }`
  replaces `headers` and `body`.
- Protocol handler results become `{ text, json? }` so plugins can supply
  structured output; images remain host-only.
- Host calls: `HostRequest { uri, input }`; SDK `read(uri, input)` and
  `exec(uri, input)` take `serde_json::Value`. `RequestHeader` is removed.
- Update the example plugin, `author_help`, the wire-shape test, and
  `docs/plugins.md` together, as required by the development guide.

## Persistence

- The session database becomes `sessions-v6.db`. `sessions-v5.db` is left
  untouched and never read. No migration code is written.
- Remove tolerant `#[serde(default)]` paths that exist only for older stored
  shapes when touching the affected types.
- `retrieval::SCHEMA_VERSION` becomes 3 so no sidecar index built from
  envelope-shaped records is reused.
- The MCP session profile keeps version 1; it is unaffected.

## Provider schema requirements

The tool schema uses an array of objects with fixed properties and one
free-form object, `input`.

- OpenAI (non-strict; Responses falls back to non-strict when a schema cannot
  be made strict) and Anthropic accept this shape.
- The Gemini path through `rig-core` 0.42 converts schemas into the legacy
  `Schema` type and drops `additionalProperties`, so `input` would arrive as an
  object without properties. The Gemini request must send the original schema
  as `parametersJsonSchema`; implement this in the existing
  `ModelRequestTransform` Google path with the original tool schemas supplied
  by the backend.
- Antigravity strips unsupported keywords in `clean_tool_schemas`; verify
  free-form `input` against the live endpoint during implementation.

These are prerequisites for the model to see the schema; they are not
compatibility shims for model mistakes.

## Phases

1. Core: step schema and executor without `for` and substitution, `input`
   in the `Protocol` trait, `ProtocolOutput`, all built-in protocols and help
   pages, MCP, WASM ABI 9, persistence bump, embedded-format rewrites,
   `sessions` protocol remnant removal, Gemini schema fix, documentation.
2. Data flow: `for`/`max`, `{{ }}` substitution, foreground pinning of
   referenced operations, shell `env`.

## Acceptance criteria

A phase is accepted only when every item in its list holds. Automated items
are tests or commands in the repository; "search" items are `rg` runs over
`src`, `sdk`, `examples`, `docs`, `AGENTS.md`, and both READMEs, excluding
this plan file, and must return no matches.

### Every phase

- `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D
  warnings`, `cargo test`, and `cargo check` pass, including the example
  plugin workspace member.
- No test needs live credentials or network access.
- The documentation checks in the development guide pass, and `README.md` and
  `README.zh-CN.md` stay equivalent.

### Phase 1

Model interface:

- A test pins the `protocol` tool schema: one required `steps` array of 1..=8
  objects; step properties `read`, `exec`, `input`, `id`, `if`, and `show`
  with fixed types; unknown step properties rejected; no `anyOf`, `oneOf`, or
  multi-type `type` anywhere in the schema.
- Validation tests cover each rejected shape: `input` as a string, both or
  neither of `read`/`exec`, an unknown step field, more than 8 steps, a
  duplicate `id`, a reference to an unknown or later step, an invalid
  expression, an unknown protocol, an unsupported operation, and a protocol
  whose help is not loaded. For each, the call is rejected, the message names
  the step and field, and a counting test protocol records zero invocations.
- Execution tests cover: independent steps with ordered `ok`/`error`
  sections; `if` true and false; a step skipped because it references a failed
  step, reported as `skipped` with the reason; an `if` reading `.ok` of a
  failed step; `show` values `all`, `errors`, and `none`; `.text` holding the
  complete text when the displayed output is truncated.

Removal (search items):

- `\*\*\* (Begin Request|End Request|Body:|Read:|Exec:)` and `requests:`
  as the tool parameter.
- `RequestHeader`, `header_value`, `header_values`, `reject_unknown_headers`,
  `parse_comparison`, `Comparison`.
- `sessions://`, `SESSIONS_BASE_URI`, and an `impl Protocol for
  SessionsPlugin`.
- `map_arguments`, `coerce_values`, `coerce_scalar`, `schema_property`,
  `render_legacy_help` in `src/builtins/mcp.rs`.
- `arguments.uri` and `$.arguments.uri` fallbacks in `src/tui`,
  `src/builtins/history.rs`, and `src/session.rs`.
- The word "header" in any protocol help page or in `docs/protocols.md`,
  except where it refers to HTTP headers of MCP or provider configuration.

Protocols:

- Each built-in protocol has a test that accepts one valid `input` per route
  and rejects an unknown `input` field with an error listing the accepted
  fields. `uri-agent-docs`, `<name>-skill`, and `wasm_plugin` reject any
  `input` field.
- A test extracts every JSON step example from every built-in help page and
  from `docs/protocols.md`, and each one passes step validation against the
  registered protocols.
- `tasks://<id>/send` delivers `text` byte-for-byte, including a trailing
  newline and an empty-string rejection.
- `search` rejects `"limit": ">=10"` and accepts `"limit": 10` with the
  existing clamps.
- Shell `script`, search `query`, finder `question`, collaboration
  `message`, and notes `content` keep their previous validation (non-empty,
  length limits).

MCP:

- Tool calls pass `input` to the server unchanged, including nested objects
  and strings containing quotes and newlines.
- `.json` equals `structuredContent`; without it, equals the parsed single
  JSON text block; otherwise `null`. `isError` yields `ok == false`.
- `resources/read` requires `input.uri`; prompt reads pass `input` as prompt
  arguments.
- Restoring a session protocol record without `help_dependencies: ["mcp"]`
  fails.

Privacy:

- History records and `searchable_records` exclude a `protocol` call when any
  step address starts with `context://`, together with its result; tests use
  the step argument shape, including a mixed call.

WASM:

- Manifests with ABI 9 load; ABI 8 is rejected with the explicit version
  error.
- The SDK wire-shape test pins the v9 `HandlerRequest::Protocol`,
  `HostRequest`, and handler result shapes.
- The example plugin round-trips `input` through its echo route, and a host
  `read`/`exec` from a plugin reaches a static protocol with `input`.

Persistence:

- Sessions are stored in `sessions-v6.db`. A test with an existing
  `sessions-v5.db` shows it is neither opened nor modified.
- Retrieval sidecars are written under `retrieval/v3/`.

Providers:

- A request-transform test shows `google-generative-ai` function declarations
  carrying `parametersJsonSchema` equal to the original tool schema, with the
  free-form `input` object intact and no lossy `parameters` field.

Interfaces:

- TUI tests render titles and details for a single read, a shell exec, and a
  multi-step call from step arguments.
- ACP tests show `tool_title` from the first step and `tool_kind` `Execute`
  when any step uses `exec`.

Documentation:

- `AGENTS.md`, both READMEs, `docs/protocols.md`, `docs/plugins.md`,
  `docs/context.md`, `docs/sessions.md`, and `docs/README.md` describe the step
  interface, `input`, ABI 9, and `sessions-v6.db`, and no longer mention the
  envelope, headers, ABI 8, or `sessions-v5.db`.

### Phase 2

- The tool schema adds `for` (string) and `max` (integer) and nothing else.
- `for` runs once per element in order; the step value is the list of element
  values; a `for` source that is not a list fails the step; a list longer than
  `max` fails the step before any element runs; `for` without `max` or `max`
  outside 1..=32 fails validation.
- Execution stops starting new operations once 64 operations have run in one
  call; the remaining steps are reported as `skipped` with that reason.
- Substitution tests: a whole-value placeholder keeps the JSON type (number
  stays a number); `${{ secrets.TOKEN }}` and other partial `{{` strings stay
  literal; `{{ "{{x}}" }}` yields the literal `{{x}}`; address substitution
  accepts scalars and rejects objects and lists; shell `script` is never
  substituted, while shell `env` values are.
- A test with a shortened foreground grace shows that an operation referenced
  by a later step is not promoted to a background task, while an unreferenced
  one still is.
- Help pages and `docs/protocols.md` document `for`, `max`, and substitution,
  and their examples pass the help-example validation test.
- This plan file is deleted.

### Manual gates before release

These need real accounts and are recorded in the release notes of the change:

- Gemini through `parametersJsonSchema` accepts free-form `input` and the
  model fills MCP tool arguments in it.
- Antigravity accepts free-form `input`; if it does not, the release notes
  state the limitation for that endpoint.
- On the weakest supported model, the same task set (single read, multi-line
  shell script, MCP call with nested arguments, conditional step) shows a
  format error rate no higher with steps than with the envelope.
